This page covers the entity model, the `IIdentityProvider` bridge that integrates with
the Granit.Identity abstraction layer, and the admin REST API for managing users, roles,
groups, and OIDC resources.

## Entities

:::note[`LocalIdentity` is credentials only — the canonical user lives elsewhere]
`LocalIdentity` is the ASP.NET Identity row that owns credentials (password hash,
lockout, claims). The framework's **canonical `User` aggregate** lives in
`Granit.Identity` and is auto-created whenever a `LocalIdentity` is created
([ADR-051](/dotnet/architecture/adr/051-user-aggregate-and-parties-bridge/) /
PR #1712). The rest of the framework references the canonical `User` for audit
fields, ownership, and tenant assignment — never `LocalIdentity` directly outside
the authentication layer.
:::

### LocalIdentity

Extends `IdentityUser<Guid>` with Granit multi-tenancy and audit support. Renamed
from the legacy `GranitUser` class to clarify that it represents *local* identity
credentials specifically (rather than the canonical user identity).

```csharp
public class LocalIdentity : IdentityUser<Guid>, IMultiTenant
{
    public string? FirstName { get; set; }              // max 256
    public string? LastName { get; set; }               // max 256
    public Guid? TenantId { get; set; }                 // IMultiTenant
    public bool IsDeleted { get; set; }                 // manual soft-delete
    public DateTimeOffset? DeletedAt { get; set; }
    public string? DeletedBy { get; set; }              // max 256
    public string? CustomAttributesJson { get; set; }   // JSON extensible attributes
    public DateTimeOffset CreatedAt { get; set; }       // audit
    public string CreatedBy { get; set; }               // audit, max 256
    public DateTimeOffset? ModifiedAt { get; set; }     // audit
    public string? ModifiedBy { get; set; }             // audit, max 256
}
```

:::caution[Design decisions]

- **No `ISoftDeletable`**: incompatible with `UserManager<T>` internal reflection
  patterns. Uses manual `IsDeleted` field with a named query filter that supports
  `IDataFilter.Disable<ISoftDeletable>()` bypass via the same `bypass || real` pattern
  as `ApplyGranitConventions`.
- **No `IConcurrencyAware`**: ASP.NET Core Identity manages its own `ConcurrencyStamp`
  property. Adding a second concurrency mechanism would cause conflicts.
- **Tenant-scoped**: Implements `IMultiTenant` with `Guid? TenantId` for GDPR-strict
  tenant isolation. Indexed on `TenantId`.

:::

### GranitRole

Extends `IdentityRole<Guid>` with an optional description.

```csharp
public class GranitRole : IdentityRole<Guid>
{
    public string? Description { get; set; }  // max 512
}
```

`GranitRole` is intentionally **not tenant-scoped**. Roles are shared globally across
all tenants so that a single RBAC matrix applies platform-wide. Tenant-specific access
is enforced at the permission/policy level, not at the role definition level.

### GranitUserGroup

Custom group entity (ASP.NET Core Identity has no native group concept). Multi-tenant
and audited with a unique constraint on `(TenantId, Name)`.

```csharp
public class GranitUserGroup : AuditedEntity, IMultiTenant
{
    public string Name { get; set; }          // max 256, unique per tenant
    public string? Description { get; set; }  // max 512
    public Guid? TenantId { get; set; }
}
```

### GranitUserGroupMember

Join entity linking a user to a group. Unique on `(GroupId, UserId)`.

```csharp
public class GranitUserGroupMember : AuditedEntity, IMultiTenant
{
    public Guid GroupId { get; set; }
    public Guid UserId { get; set; }
    public Guid? TenantId { get; set; }
}
```

### OpenIddict entities

All four OpenIddict entities are extended with `IMultiTenant` for tenant isolation:

| Entity | Base class | Table |
|--------|-----------|-------|
| `GranitOpenIddictApplication` | `OpenIddictEntityFrameworkCoreApplication<Guid, ...>` | `openiddict_applications` |
| `GranitOpenIddictAuthorization` | `OpenIddictEntityFrameworkCoreAuthorization<Guid, ...>` | `openiddict_authorizations` |
| `GranitOpenIddictScope` | `OpenIddictEntityFrameworkCoreScope<Guid>` | `openiddict_scopes` |
| `GranitOpenIddictToken` | `OpenIddictEntityFrameworkCoreToken<Guid, ...>` | `openiddict_tokens` |

Applications and scopes with `TenantId == null` are global (visible to all tenants).

## IIdentityProvider bridge

`Granit.Identity.Local.AspNetIdentity` registers `AspNetIdentityProvider` as the
`IIdentityProvider` implementation, replacing the default `NullIdentityProvider`.
It implements all 6 sub-interfaces of the Granit.Identity abstraction layer:

| Interface | Implementation detail |
|-----------|---------------------|
| `IIdentityUserReader` | `UserManager<LocalIdentity>.Users` LINQ queries |
| `IIdentityUserWriter` | `UserManager.CreateAsync()`, `UpdateAsync()` |
| `IIdentityRoleManager` | `RoleManager<GranitRole>` operations |
| `IIdentityGroupManager` | Direct EF Core queries on `GranitUserGroup` |
| `IIdentityPasswordManager` | `UserManager.ResetPasswordAsync()`; `reset-email` publishes `PasswordResetRequestedEto` (delivered by `Granit.Identity.Local.Notifications`) |
| `IIdentityCredentialVerifier` | `UserManager.CheckPasswordAsync()` |

Session management is **not** one of these interfaces — it moved to the topology-agnostic
[`IUserSessionManager`](/dotnet/security/identity/#user-sessions--devices). In an OpenIddict
deployment the manager is backed by `OpenIddictUserSessionProvider`
(`Granit.OpenIddict`): every **valid refresh token** in the OpenIddict token store is one
live session, keyed by token id.

### Provider capabilities

`AspNetIdentityProviderCapabilities` declares what this provider supports:

```csharp
ProviderName = "AspNetIdentity"
SupportsIndividualSessionTermination = false
SupportsNativePasswordResetEmail = true
SupportsGroupHierarchy = false
SupportsCustomAttributes = true
MaxCustomAttributes = int.MaxValue
SupportsCredentialVerification = true
SupportsUserCreation = true
```

:::note[Session revocation is real — it revokes the refresh token]
`SupportsIndividualSessionTermination = false` reflects the **ASP.NET Identity provider**
itself; it does not gate the canonical session API. Revoking a session through
[`/sessions`](/dotnet/security/identity/#user-sessions--devices) calls
`OpenIddictUserSessionProvider.RevokeAsync`, which looks the session up by token id and
calls `IOpenIddictTokenManager.TryRevokeAsync` to **revoke the underlying refresh token**.
The session genuinely disappears: the next time that client tries to refresh its access
token, OpenIddict rejects the revoked refresh token. (The earlier no-op behaviour is gone —
revocation now changes server state, not just the response.) "Revoke all others" applies
the same revocation to every refresh token except the caller's current one.
:::

:::caution
Do **NOT** add `Granit.Identity.Federated.EntityFrameworkCore` alongside `Granit.Identity.Local.AspNetIdentity`.
It would create a redundant `UserCache` layer. `AspNetIdentityUserLookupService` queries
`UserManager<LocalIdentity>` directly.
:::

## Identity settings (ASP.NET Core)

`AddGranitOpenIddict()` configures ASP.NET Core Identity with
secure defaults:

```csharp
options.User.RequireUniqueEmail = true;
options.Lockout.MaxFailedAccessAttempts = 5;
options.Lockout.DefaultLockoutTimeSpan = TimeSpan.FromMinutes(15);
options.SignIn.RequireConfirmedEmail = true;
```

## Admin REST API

All admin endpoints are under `/api/admin` (configurable via `OpenIddictEndpointsOptions.AdminRoutePrefix`)
and require authorization. Permission constants are defined in `OpenIddictPermissions`.

### Permissions

```csharp
public static class OpenIddictPermissions
{
    public const string GroupName = "OpenIddict";

    public static class Users         // Read, Create, Manage, Delete, Impersonate
    public static class Roles         // Read, Create, Delete
    public static class Groups        // Read, Create, Manage, Delete
    public static class Applications  // Read, Create, Manage, Delete, Rotate
    public static class Scopes        // Read, Create, Manage, Delete
    public static class Authorizations // Read, Revoke
}
```

All permission strings follow the `[Group].[Resource].[Action]` convention
(e.g., `OpenIddict.Users.Read`).

### Users (`/api/admin/users`)

| Method | Path | Permission | Description |
|--------|------|------------|-------------|
| `GET` | `/` | `Users.Read` | Paginated list (`?search`, `?page`, `?pageSize`) |
| `GET` | `/{userId}` | `Users.Read` | User detail with roles and groups |
| `POST` | `/` | `Users.Create` | Admin-initiated user creation (no email confirmation) |
| `DELETE` | `/{userId}` | `Users.Delete` | Soft-delete + token revocation |
| `POST` | `/{userId}/impersonate` | `Users.Impersonate` | Issue impersonation token |

**Create user request:**

```json
{
  "email": "jane@example.com",
  "firstName": "Jane",
  "lastName": "Doe",
  "temporaryPassword": "Temp123!@#"
}
```

### Roles (`/api/admin/roles`)

| Method | Path | Permission | Description |
|--------|------|------------|-------------|
| `GET` | `/` | `Roles.Read` | List all roles with descriptions |
| `POST` | `/` | `Roles.Create` | Create a new role |
| `DELETE` | `/{roleName}` | `Roles.Delete` | Delete role (409 if has members) |
| `GET` | `/{roleName}/members` | `Roles.Read` | Paginated list of role members |

### Groups (`/api/admin/groups`)

| Method | Path | Permission | Description |
|--------|------|------------|-------------|
| `GET` | `/` | `Groups.Read` | Paginated list for current tenant |
| `POST` | `/` | `Groups.Create` | Create group (409 on duplicate name within tenant) |
| `DELETE` | `/{groupId}` | `Groups.Delete` | Delete group + cascade memberships |
| `POST` | `/{groupId}/members` | `Groups.Manage` | Add user to group |
| `DELETE` | `/{groupId}/members/{userId}` | `Groups.Manage` | Remove user from group |

### OIDC Applications (`/api/admin/oidc/applications`)

| Method | Path | Permission | Description |
|--------|------|------------|-------------|
| `GET` | `/` | `Applications.Read` | Paginated list (`?page`, `?pageSize`) of registered OIDC clients |
| `POST` | `/` | `Applications.Create` | Register a new OIDC application (409 if client ID exists) |
| `DELETE` | `/{clientId}` | `Applications.Delete` | Delete app + authorizations + tokens |
| `POST` | `/{clientId}/rotate-secret` | `Applications.Rotate` | Rotate client secret (returns plaintext once) |

All admin list endpoints (`applications`, `scopes`, `authorizations`) return a
`PagedResult<T>` envelope — `{ "items": [...], "totalCount": n, "hasMore": bool }` —
paginated with `?page` (1-based, default 1) and `?pageSize` (default 25, max 100).

**Create application request:**

```json
{
  "clientId": "my-spa",
  "displayName": "My SPA (PKCE)",
  "generateClientSecret": false,
  "permissions": ["ept:authorization", "ept:token", "gt:authorization_code"],
  "redirectUris": ["https://app.example.com/callback"],
  "postLogoutRedirectUris": ["https://app.example.com"]
}
```

Set `generateClientSecret: true` to have the server mint a cryptographically strong
secret for a confidential client and return it once in `generatedClientSecret` — the
admin never has to invent secret material. Alternatively pass `clientSecret` explicitly;
omit both for a public client. An admin-supplied secret is never echoed back.

**Secret rotation response:** `{ clientId, displayName, newClientSecret }` — the new
secret is returned **once only**. It is hashed before storage and cannot be retrieved later.

### OIDC Scopes (`/api/admin/oidc/scopes`)

| Method | Path | Permission | Description |
|--------|------|------------|-------------|
| `GET` | `/` | `Scopes.Read` | List all scopes with resources |
| `POST` | `/` | `Scopes.Create` | Register a new scope (409 if name exists) |
| `DELETE` | `/{scopeName}` | `Scopes.Delete` | Delete scope (404 if not found) |

**Create scope request:**

```json
{ "name": "api", "displayName": "API Access", "resources": ["my-api"] }
```

**Scope response:** `{ id, name, displayName }`

### OIDC Authorizations (`/api/admin/oidc/authorizations`)

| Method | Path | Permission | Description |
|--------|------|------------|-------------|
| `GET` | `/?subject=&clientId=` | `Authorizations.Read` | Paginated list, optionally filtered server-side by `subject` (user id) and/or `clientId` |
| `DELETE` | `/{authorizationId}` | `Authorizations.Revoke` | Revoke single authorization + tokens |
| `DELETE` | `/user/{userId}` | `Authorizations.Revoke` | Revoke all for user (GDPR / security incident) |

**Authorization response:** `{ id, subject, clientId, status, type, scopes }`. An unknown
`clientId` filter yields an empty page.

The `DELETE /user/{userId}` endpoint iterates all authorizations for the subject and
revokes each one — used for GDPR erasure requests and security incident response.
